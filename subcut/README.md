# Sub-Cut — サブスク断捨離・一元管理(試作版)

カード明細からサブスクの引き落としを自動で見つけて一覧にし、解約ページまで案内するウェブアプリの試作です。
一献のサイトとは別のアプリで、`subcut/` の中だけで完結しています(一献のページ・sitemap・共通部品には影響しません。`noindex` を付けています)。

公開後の住所: `https://<ユーザー名>.github.io/ikkon/subcut/`
手元で見る: リポジトリの一番上で `python3 -m http.server 8000` → `http://localhost:8000/subcut/`

## できること(MVP)

| 機能 | 中身 |
|---|---|
| 明細の取りこみ | カード会社の明細 CSV を読む。見出しの有無・列の並び・Shift_JIS/UTF-8 を自動判定。複数月をまとめて読める |
| 自動検知 | 30サービスの辞書で名寄せ(`APPLE.COM/BILL`・`OPENAI *CHATGPT` など)。辞書にない店も「金額がほぼ同じ・間隔が一定」のくり返しを毎週/毎月/3か月/毎年で検知。ふだんの買い物は拾わない |
| 一覧 | 月額合計・年額換算・次回引き落とし日。電気などの固定費は分けて「残す」扱い |
| 見直し候補 | 「最近使った?」の回答、同じ分類(AI・動画・音楽・読書)の重複、最近の請求が止まったもの、解約後の請求を知らせる |
| 解約ナビ | サービスごとの手順と公式の解約ページへのリンク。次回日までの残り日数、年間の削減額、注意点(Adobe の途中解約手数料、Apple/Google 経由の契約など) |
| 削減額 | 解約したものの年間削減額・これまでに浮いた額。成果報酬にした場合の手数料試算 |
| 更新日の通知 | 次回引き落とし日の前日に通知する .ics を書き出し、手持ちのカレンダーに入れられる |
| プライバシー | 明細はブラウザの中だけで読み、保存するのは検知結果だけ(localStorage)。JSON で書き出し・読みこみ |

## ファイル

```
subcut/index.html   画面
subcut/style.css    デザイン(ライト・ダーク)
subcut/app.js       画面の処理・保存
subcut/detect.js    CSV の読み取りとくり返しの検知(画面に依存しない)
subcut/services.js  サービス辞書(検知の正規表現・解約ページ・手順)
subcut/sample.csv   お試し用の6か月分の明細(架空)
subcut/sw.js ほか   オフラインで開くための PWA の部品
tools/test_subcut.js  検知ロジックのテスト(node tools/test_subcut.js)
```

サービスを足すときは `services.js` の `SERVICES` に1件足すだけです。足したら `node tools/test_subcut.js` を流してください。

## ビジネスモデル

- **ターゲット**: AI ツールや動画・音楽など複数のサブスクを契約し、管理しきれずに放置しがちなビジネスパーソン
- **無料**: 検知・一覧・解約ナビ(集客と習慣化)
- **プレミアム ¥300/月**: 更新日前のプッシュ通知、複数カード・口座のまとめ、家族共有
- **解約おまかせ(成果報酬)**: 削減できた月額の1か月分。解約できなければ0円
  - 例: 月 ¥9,920 の見直し候補をすべて解約 → 手数料 ¥9,920、利用者は1年で ¥109,120 が手元に残る

試作版の料金ボタンは「近日公開」で、決済はありません。

## 本番にするまでに要ること

1. **カード明細の自動連携** — 銀行・カード会社の API(または Moneytree LINK などの家計簿アグリゲーション API)につなぐ。
   利用者の口座・カード情報を API で取得するサービスは、**電子決済等代行業**の登録が必要になる場合があります。最初は既存のアグリゲーターと提携するのが現実的です。
2. **解約代行** — 利用者の ID・パスワードを預かって代わりに手続きするのは、情報管理と規約(多くのサービスはアカウントの第三者利用を禁止)の両面で負担が大きい。
   まずは「手順を案内し、利用者が自分で押す」ナビの精度を上げ、代行は手続きが書面・電話で済むものから始めるのが安全です。報酬を取って代わりに交渉する形は法律上の論点(弁護士法など)があるので、事業化の前に専門家に確認してください。
3. **サーバーとアカウント** — 複数端末の同期、プッシュ通知、決済(Stripe など)、プライバシーポリシーと利用規約。
4. **辞書の運用** — 解約ページの URL は変わるので、定期的なリンク切れチェックと、利用者からの「リンクが違う」報告の仕組み。

## 検証したこと

- `node tools/test_subcut.js`: CSV の読み取り(引用符・カンマ入り金額・見出しなしの明細)、日付・金額の書式、名寄せ、サンプル明細での検知(12件を検知し、コンビニ・Amazon の買い物などは拾わない)、年払いの判定
- ヘッドレス Chromium でパソコン幅・スマホ幅(ダーク)の表示、サンプル読みこみ → 使用状況の回答 → 解約ナビ → 解約済み → 削減額の流れ、横スクロールが出ないこと
