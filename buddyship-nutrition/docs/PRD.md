## 1. 背景と目的

株式会社Buddyshipの**リハビリ特化型デイサービス**の利用者が、**自宅で食べた食事**を写真で記録し、カロリーとPFC(たんぱく質・脂質・炭水化物)の摂取量を推定できるようにする。InBody の身体組成と並べ、利用者本人と同意済みの担当スタッフが経時変化を確認できるようにする。

- AI は写真から**食品名と提供量(重量)の候補**を出すだけ。栄養値は**食品成分マスターに基づく決定論的計算**で求める。
- 利用者(またはスタッフ)が、提供量と**食べた割合**を確認・修正してから保存する。
- 未記録の食事を「食べていない(0 kcal)」として扱わない。部分的な記録を1日の総摂取量と誤認させない。

### 1.1 安全要件(2026-11-10 追加。すべての機能に優先する)

| ID | 要件 | 実現方法 |
|---|---|---|
| SAFE-1 | アプリの目的は、食事の記録・栄養の推定・身体組成の可視化に限る | 設定画面「このアプリについて」に目的を明示。機能追加時は SAFE-2〜4 に反しないことを確認 |
| SAFE-2 | 低栄養・サルコペニア・その他の疾患を AI が診断しない | AI の出力スキーマは食品名と提供量だけ(診断の項目がない)。画面文言の自動検査で判定表現を禁止 |
| SAFE-3 | 個人別の摂取目標量・食事制限を自動設定しない | 目標量・制限を保存する項目を持たない。画面文言の自動検査 |
| SAFE-4 | 疾患に応じた治療的栄養指導を自動生成しない | 指導文を生成する機能を作らない。AI に文章を生成させない。画面文言の自動検査 |
| SAFE-5 | 食事記録が不完全な日は、1 日の総摂取量として表示しない | `packages/nutrition/src/daily.ts` が見出しを決める(§6.3)。64 通りの記録状況をテスト |
| SAFE-6 | 推定値には誤差があることを明示する | 栄養値の近くに「推定」と、実際とは差がある旨を必ず表示 |
| SAFE-7 | 食品成分表の出典とバージョンを表示する | 「日本食品標準成分表(八訂)増補2023年から引用」と正誤表の反映日を表示(`packages/nutrition/src/source.ts`) |
| SAFE-8 | 将来、管理栄養士が監修できるよう、栄養計算ルールを独立したモジュールにする | `packages/nutrition`(列の対応・値の解釈・計算・丸め・1 日の表示・出典)。規則の版を明細に保存 |

### 1.2 本製品がしないこと

| 項目 | 理由 |
|---|---|
| 医療診断、低栄養・栄養不足・過剰の自動判定、疾病リスク判定 | 医療行為・医療機器プログラムに該当し得る |
| 推奨摂取量・目標値の自動提示、食事指導文の自動生成 | 同上。腎疾患・糖尿病等で制限のある利用者もおり、一律の目安は危険 |
| 体重減少などの自動アラート | 同上。数値の事実(前回差)のみ表示(D-15 確定) |
| デイサービスで提供された食事の記録 | 確定仕様で対象外 |
| 家族アカウント | Phase 1 対象外 |
| AI が出した栄養値の採用 | 決定論的計算の原則 |
| 利用者データの開発・テスト流用 | 合成データのみ使用 |

## 4. ユースケース

### UC-1 自宅の食事を記録する(本人)
1. 「ごはんを記録」→ 写真を撮る/選ぶ(写真なしで記録も可)。
2. 「いつ食べたか」(日付・食事区分・おおよその時刻)を選ぶ。**登録日時とは別に保存**。
3. 「どこで食べたか」は**自宅のみ**。画面で「自宅で食べた食事を記録してください。デイサービスの食事は記録しません」と明示。
4. AI が食品と**提供量**を推定 → 食品成分マスターの候補とともに表示(推定値と明示)。
5. 利用者が食品・提供量を直し、**どれくらい食べたか**(全部/半分くらい など)を選ぶ。
6. 摂取量 = 提供量 × 食べた割合 で、マスターから栄養値を計算。
7. 保存。

### UC-2 スタッフが食事を代理入力する
- 来所時の聞き取りや、利用者が見せた写真をもとに入力。`meals:write` の同意と担当割当が必要。
- 写真は利用者の端末から見せてもらう/スタッフ端末で撮影する方法 **[未決 D-27]**。
- 入力経路(本人/スタッフ)・入力者・情報源(写真/聞き取り)を記録。

### UC-3 食べなかった・デイサービスだった を記録する(欠測管理)
- 食事区分ごとに「記録した」「食べなかった」「デイサービスで食べた(対象外)」「未記録」を区別する(§6.3)。

### UC-4 食事を修正・削除する
- 本人は自分の全記録を修正・削除可。スタッフは自分が代理入力した記録のみ修正可(期限付き)**[未決 D-07]**。

### UC-5 InBody を記録する(本人/同意済みスタッフ)
- デイサービスでの測定値をスタッフが代理入力するのが主になる想定。

### UC-6 経過を見る(本人/同意済みスタッフ)
- 身体組成の推移、食事記録の推移(記録状況と合わせて表示)。

### UC-7 担当利用者ダッシュボード(スタッフ)
- 担当利用者ごとの:最終記録日、直近 7 日の記録状況、最新 InBody と前回差。評価・アラートは出さない。

### UC-8 同意・担当の管理
- 利用者が担当スタッフごとにスコープを付与・撤回。管理者が担当割当を管理。

## 5. 機能要件

### 5.1 認証・プロフィール
- FR-AUTH-1 3ロール。ロールは管理者のみ変更可(クライアントの値でロールを決めない)。
- FR-AUTH-2 ログイン方式 **[未決 D-04]**。高齢者がメールを使えない場合を想定し、事業所での初期設定支援を前提とする。
- FR-AUTH-3 スタッフ・管理者は MFA 必須(仮)。共用タブレットでの自動ログアウト。
- FR-AUTH-4 プロフィール:表示名、タイムゾーン(既定 Asia/Tokyo)、文字サイズ設定。**氏名・生年月日・介護度・病名などは持たない**(最小収集)**[未決 D-28]**。
- FR-AUTH-5 利用規約・プライバシーポリシー・AI 外部送信・スタッフ共有の同意取得と版の記録。

### 5.2 担当割当
- FR-ASSIGN-1 管理者が利用者とスタッフを割り当て・解除。複数担当可。
- FR-ASSIGN-2 担当解除時の同意の扱い **[未決 D-07]**(仮:自動撤回)。

### 5.3 食事記録
- FR-MEAL-1 **食事場所は `home` のみ許可**(DB 制約で強制。将来の拡張のため列は持つ)。
- FR-MEAL-2 **摂取日時(eaten_at)と登録日時(recorded_at)を別々に保存**。摂取日時の精度(時刻まで/食事区分のみ)を保存。
- FR-MEAL-3 食品明細ごとに以下を**分けて保存**:
  - `ai_estimated_served_g`:写真から AI が推定した提供量(AI 解析時のみ)
  - `served_g`:利用者/スタッフが確認・修正した提供量
  - `intake_percent`:食べた割合(0〜100 の整数 %)
  - `consumed_g` = `served_g` × `intake_percent` / 100:計算に使う摂取量
- FR-MEAL-4 栄養値 = Σ(100g あたり成分値 × `consumed_g` / 100)。サーバーで計算し、使った成分値・マスター版・計算規則の版をスナップショット保存。成分値は食品成分表の標準的な成分値(エネルギー `ENERC_KCAL`、たんぱく質 `PROT-`、脂質 `FAT-`、炭水化物 `CHOCDF-`。D-18 ②)。**エネルギーは成分表の公表値を使い、P/F/C から再計算しない**。成分表で未測定(`-`)の成分は 0 とみなさず「一部の値なし」と表示する。
- FR-MEAL-5 食べた割合の入力:「全部 / ほとんど(8割) / 半分 / 少し(2割) / 食べなかった」+ 10% 刻みの詳細入力 **[未決 D-29]**。明細ごとと食事全体の一括の両方。
- FR-MEAL-6 AI 解析は失敗しても手入力(食品検索+量)で記録できる。
- FR-MEAL-7 すべての栄養値表示に「推定」ラベルと、実際とは差がある旨(SAFE-6)。食品成分表の出典と版を表示(SAFE-7)。
- FR-MEAL-8 画像は非公開保存、短期保持(仮 30 日)**[未決 D-09]**。
- FR-MEAL-9 AI 解析回数の上限(利用者/スタッフ・事業所・月)。

### 5.4 欠測管理(§6.3 も参照)
- FR-GAP-1 食事区分(朝・昼・夕)ごとの状態を保持:`recorded`(記録あり) / `skipped`(食べなかった) / `dayservice`(デイサービスで食べた=対象外) / 未記録(行なし)。間食は欠測管理の対象外(任意記録)。
- FR-GAP-2 未記録を 0 として合計・平均に含めない。
- FR-GAP-3 日の合計は「**記録された自宅の食事の合計**」と表記し、記録状況(例:「朝 ✓ 昼 デイ 夕 未記録」)を常に併記。
- FR-GAP-4 グラフ・平均は、主食事3区分すべてが「記録/食べなかった/デイサービス」で埋まった日と、それ以外の日を区別して表示する。「1日の総摂取量」という表現は使わない。
- FR-GAP-5 過去の未記録分は、後から記録または「食べなかった」を入力できる(摂取日時と登録日時が別なので遡及入力が可能)。遡及可能期間 **[未決 D-30]**(仮:7日)。

### 5.5 InBody
- FR-BODY-1 項目:体重、骨格筋量、体脂肪量、体脂肪率、測定日時、測定機種。
- FR-BODY-2 範囲チェック、整合性の警告(保存は可)。
- FR-BODY-3 入力経路・入力者を記録。
- FR-BODY-4 機器からの自動取込は対象外 **[未決 D-12]**。

### 5.6 閲覧・ダッシュボード
- FR-VIEW-1 本人ホーム:今日の記録状況、記録された食事の推定合計、最新 InBody。
- FR-VIEW-2 身体組成の推移グラフ(期間切替)と数値表。
- FR-VIEW-3 スタッフの担当利用者ダッシュボード(UC-7)。同意スコープがない項目は表示しない。

### 5.7 監査・削除・エクスポート・バックアップ
- FR-DATA-1 監査ログ(作成・更新・削除、スタッフの閲覧・代理入力、拒否、同意変更、エクスポート、削除)。
- FR-DATA-2 本人のデータエクスポート(JSON/CSV **[未決 D-16]**)。
- FR-DATA-3 アカウント削除と利用者データの削除。介護記録としての保存義務との関係 **[未決 D-20]**。
- FR-DATA-4 バックアップと復元手順、復元訓練(Sprint 4)。目標 RPO/RTO **[未決 D-31]**。

## 6. 食事記録のデータ上の規則

### 6.1 場所
`meal_location` は列挙型とし、Phase 1 は `home` のみ。CHECK 制約で `home` 以外を拒否。

### 6.2 量
```
提供量 served_g      … 利用者・スタッフが確認した量(初期値は AI 推定値 or 手入力)
食べた割合 intake_percent … 0〜100(整数 %)
摂取量 consumed_g    = served_g × intake_percent / 100
栄養値               = 成分値(100g あたり) × consumed_g / 100
```
AI 推定値 `ai_estimated_served_g` は上書きせず残す(精度評価用)。

### 6.3 欠測
| 状態 | 意味 | 合計への扱い |
|---|---|---|
| recorded | 食事を記録した | 合計に含める |
| skipped | 本人/スタッフが「食べなかった」と明示 | 0 として扱ってよい(明示された 0) |
| dayservice | デイサービスで食べた(記録対象外) | 合計に含めない。「対象外」と表示 |
| (未記録) | 何も入力されていない | **0 として扱わない**。「未記録」と表示 |

「その日の自宅の食事がすべて記録済み」の判定 = 朝・昼・夕すべてが recorded / skipped / dayservice のいずれか。それでも表示は「自宅で記録された食事の合計」とし、デイサービス分を含まないことを明記する。

## 8. 将来拡張への配慮

- 全データに `organization_id`、`facility_id` を持たせ、スタジオ・複数拠点に展開可能にする。
