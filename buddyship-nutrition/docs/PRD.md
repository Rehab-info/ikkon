## 1. 背景と目的

株式会社Buddyshipのトレーニングスタジオ利用者が、日々の食事と身体組成(InBody)を一か所で記録・振り返りできるようにする。

- 食事写真をAIが解析し、**食品名と重量の候補**を出す。
- カロリー・PFC は **食品成分マスターに基づく決定論的計算** で求める(AIが出した栄養値は採用しない)。
- AIの推定結果は必ず利用者が確認・修正してから保存する。
- InBody の測定値を記録し、食事と身体組成の推移を並べて見られるようにする。
- 担当スタッフは、利用者の同意がある範囲に限り閲覧・InBody代理入力ができる。

### 1.1 本製品がしないこと(スコープ外・禁止)

| 項目 | 理由 |
|---|---|
| 医療診断、疾病リスク判定 | 医療行為・医療機器プログラムに該当し得るため(SECURITY §9) |
| 栄養不足・過剰の自動診断、「〇〇が足りません」等の断定表示 | 同上。表示は「推定摂取量」の事実のみ |
| 目標摂取量の自動処方 | 同上。目標値は Phase 1 では扱わない **[未決 D-15]** |
| AIによる栄養値の直接出力の採用 | 決定論的計算の原則 |
| 利用者データの開発・テストへの流用 | 合成データのみ使用 |
| 他利用者とのランキング・共有 | Phase 1 範囲外 |

## 2. 利用者とロール

| ロール | 想定者 | できること(Phase 1) |
|---|---|---|
| 利用者 (member) | スタジオ会員 | 自分の食事記録・修正・削除、自分のInBody入力・修正・削除、同意の付与・撤回、データのエクスポート・削除 |
| スタッフ (staff) | トレーナー | **担当割当** かつ **有効な同意範囲** がある利用者のみ:食事・InBodyの閲覧、InBodyの代理入力。食事の修正は不可 |
| 管理者 (admin) | Buddyship 運営 | スタッフの登録・停止、担当割当の管理、監査ログ閲覧、利用量上限の設定。**利用者の食事・身体データの閲覧権限は持たない(既定)** **[未決 D-05]** |

1人が複数ロールを持つ場合(例:スタッフ兼利用者)の扱いは **[未決 D-06]**。

## 3. ユースケース

### UC-1 食事を記録する(利用者)
1. 「食事を記録」→ 撮影 or 画像選択。
2. 端末側で縮小・再エンコード(位置情報などのメタデータ除去)。
3. 非公開ストレージにアップロード。
4. サーバー(Edge Function)がAI解析 → 食品名・推定重量の構造化データを受け取る。
5. サーバーが食品成分マスターと照合し、候補食品を付けて返す。
6. 画面に「推定値」と明示して表示。利用者は食品の差し替え・重量の変更・追加・削除ができる。
7. 変更のたびに栄養値をマスターから再計算。
8. 利用者が「保存」を押した時点で食事履歴に確定保存。

AI解析が失敗・上限到達の場合は、**手入力(食品検索+重量)** で同じ画面から記録できる。

### UC-2 食事を修正・削除する(利用者本人のみ)
履歴から開き、食品・重量・食事区分・日時を変更。保存時にマスターから再計算。

### UC-3 InBody を記録する(利用者 or 同意済み担当スタッフ)
体重・骨格筋量・体脂肪量・体脂肪率・測定日時・測定機種を入力。入力者(本人/スタッフ)を記録。

### UC-4 推移を見る(利用者、同意済み担当スタッフ)
ダッシュボード:今日の推定摂取カロリー・PFC、食事履歴、最新InBody、身体組成の推移グラフ。

### UC-5 同意を管理する(利用者)
担当スタッフごとに、範囲(食事閲覧 / InBody閲覧 / InBody代理入力)を付与・撤回。撤回は即時に効く。

### UC-6 スタッフ・担当を管理する(管理者)
スタッフ招待・停止、利用者への担当割当・解除。

### UC-7 データのエクスポート・削除(利用者)
自分のデータをJSON(+CSV **[未決 D-16]**)でダウンロード。アカウントと全データを削除。

## 4. 機能要件

### 4.1 認証・権限
- FR-AUTH-1 3ロール(member / staff / admin)。ロールは管理者のみ変更可。クライアントが送る値でロールを決めない。
- FR-AUTH-2 スタッフのアクセスは「有効な担当割当」**かつ**「有効な同意(該当範囲)」の両方が成立する場合のみ許可。判定はDB側で毎回行う。
- FR-AUTH-3 同意撤回・担当解除の後は、次のリクエストから拒否する(キャッシュ・トークンに権限を持たせない)。
- FR-AUTH-4 ログイン方式は **[未決 D-04]**(仮:メールOTP/マジックリンク)。スタッフ・管理者は MFA 必須(仮)。
- FR-AUTH-5 利用規約・プライバシーポリシー・AI外部送信への同意を初回に取得し、版を記録する。

### 4.2 食事AI
- FR-MEAL-1 画像はJPEG/PNG/WebP/HEIC **[未決 D-11 HEIC]** を受け付け、端末でWebP/JPEGに再エンコードし長辺1600px以下に縮小(仮)。
- FR-MEAL-2 サーバー側で形式(マジックバイト)・サイズ・寸法を再検証。
- FR-MEAL-3 AI呼び出しはEdge Functionからのみ。APIキーはサーバーの秘密情報としてのみ保持。
- FR-MEAL-4 AI出力は Zod スキーマで検証。食品名・推定重量(g)・信頼度・料理/食材区分のみを受け取る。栄養値は受け取らない(受け取っても破棄)。
- FR-MEAL-5 食品成分マスターとの照合(名称+別名辞書+あいまい検索)で候補を最大5件提示。
- FR-MEAL-6 栄養値 = Σ(100gあたり成分値 × 重量g / 100)。丸め規則は DATABASE §6。
- FR-MEAL-7 保存時に「使用した成分値のスナップショット」と「マスター版」を食事明細に保存し、後でマスターが更新されても過去記録が変わらないようにする。
- FR-MEAL-8 すべての栄養値表示に「推定値」ラベル。
- FR-MEAL-9 AI解析回数の上限(利用者ごと日次・全体月次)。上限超過時は手入力に誘導。
- FR-MEAL-10 食事画像は非公開バケットに保存し、保持期間経過後に自動削除(仮:30日)**[未決 D-09]**。
- FR-MEAL-11 食事区分:朝食・昼食・夕食・間食。

### 4.3 InBody
- FR-BODY-1 項目:体重(kg)、骨格筋量(kg)、体脂肪量(kg)、体脂肪率(%)、測定日時、測定機種(選択式+その他)。
- FR-BODY-2 値の範囲チェック(DATABASE §5)と整合性の警告(体脂肪率 ≒ 体脂肪量/体重 から大きく外れる場合に**警告のみ**、保存は可)。
- FR-BODY-3 入力者・入力経路(本人/スタッフ代理)を記録。
- FR-BODY-4 スタッフ代理入力の修正・削除は **[未決 D-07]**(仮:入力したスタッフが24時間以内のみ修正可、本人はいつでも削除可)。
- FR-BODY-5 InBody機器からの自動取込(LookinBody 等)は Phase 1 対象外 **[未決 D-12]**。

### 4.4 ダッシュボード
- FR-DASH-1 今日(利用者のタイムゾーン、既定 Asia/Tokyo)の推定摂取カロリーとPFC。
- FR-DASH-2 直近の食事履歴。
- FR-DASH-3 最新InBodyと前回差。
- FR-DASH-4 身体組成の推移グラフ(体重・骨格筋量・体脂肪量・体脂肪率、期間切替 1/3/6/12か月)。
- FR-DASH-5 日別摂取カロリーの推移(任意表示)。
- FR-DASH-6 評価的な文言(良い/悪い、不足/過剰)は表示しない。

### 4.5 同意管理
- FR-CONS-1 同意は「利用者 × 担当スタッフ × 範囲」単位。範囲:`meals:read` / `body:read` / `body:write`。
- FR-CONS-2 付与・撤回の履歴を残す(撤回しても過去の付与記録は消さない)。
- FR-CONS-3 撤回後の再付与は新しいレコードとして記録。
- FR-CONS-4 同意文面の版を記録。

### 4.6 データ権利
- FR-DATA-1 エクスポート:プロフィール・食事(明細含む)・InBody・同意履歴。画像は含める/含めない **[未決 D-16]**。
- FR-DATA-2 削除:アカウント削除で利用者データと画像を削除。監査ログは仮名化して保持 **[未決 D-10]**。
- FR-DATA-3 削除の取消猶予期間 **[未決 D-10]**(仮:なし、即時)。

## 6. 将来拡張を見据えた設計方針

- **組織・拠点**:全利用者データに `organization_id`(+`facility_id`)を持たせ、RLSの判定関数に組織境界を含める。Phase 1 は1組織1拠点で運用。
- **女性アスリート支援**:月経周期など要配慮性の高いデータを追加しうるため、データ種別ごとに同意範囲を拡張できる設計(範囲を列挙型で増やす)。
- **産業保健**:健康診断結果は要配慮個人情報。企業(雇用主)への開示制限が強いため、Phase 1 の「担当スタッフ」とは別の閲覧主体モデルが必要。今は作らないが、閲覧主体を `staff` に固定したテーブル設計にしない。

## 7. 成功指標(限定試験)

| 指標 | 目標(仮) |
|---|---|
| AI候補の食品が利用者の最終選択と一致した割合(Top-1 / Top-5) | 計測して報告(目標値は試験後に決める) |
| 重量推定の誤差(利用者修正後との差の中央値) | 計測して報告 |
| 修正なしで保存された割合 | 計測して報告 |
| 週あたり記録日数 | 計測して報告 |
| 権限違反・情報漏えい | 0件 |

※ 精度は「利用者の修正後」を正とみなす簡易評価。厳密な精度検証用には、計量済みの合成テスト画像セット(スタッフが自分で用意した料理)を別途用意する **[未決 D-14]**。
