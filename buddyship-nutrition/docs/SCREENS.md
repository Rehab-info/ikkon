# SCREENS — 画面仕様

- 文書版: **v2.0 ドラフト(承認待ち)**

## 1. 高齢者向け UI の共通ルール

| 項目 | ルール |
|---|---|
| 文字 | 本文 18px 以上、見出し 24px 以上。設定で「大きく(20px)」「とても大きく(22px)」。端末の文字サイズ設定にも追従 |
| ボタン | 高さ 56px 以上、幅は画面いっぱいを基本。主操作は1画面に1つ、画面下部に固定 |
| 色 | コントラスト比 4.5:1 以上(大きい文字も同等を目標)。色だけで意味を伝えない(✓・文字を併記) |
| 言葉 | 専門用語・カタカナを避ける。「PFC」→「たんぱく質・脂質・炭水化物」、「アップロード」→「写真を送る」、「同意を撤回」→「見せるのをやめる」(説明文では正式な語も併記) |
| 操作 | スワイプ・長押し・ダブルタップに依存しない。数値はキーボード入力でなく「−/+」ボタンと選択肢を基本にし、細かい入力は任意 |
| 流れ | 1 画面 1 つの質問(ウィザード形式)。「戻る」で前の質問に戻れる。保存前に確認画面 |
| 取り消し | 削除は確認ダイアログ。保存直後に「取り消す」を数秒表示(削除の取り消しはサーバー側の論理削除ではなく、確認ダイアログで防ぐ) |
| 時間制限 | 利用者画面に操作の時間制限を設けない(スタッフ共用端末の自動ログアウトは別) |
| エラー | 何が起きたか・次に何をすればよいかを平易な文で。赤色だけに頼らない |
| 読み上げ | すべての操作要素にラベル。画像には代替テキスト |
| 推定値 | 栄養値の近くに必ず「推定」と表示 |
| 評価語 | 良い/悪い/不足/過剰、赤/緑の良否色を使わない |

文言・操作性は、試験前にデイサービスのスタッフと利用者数名でユーザビリティ確認を行い修正する(Sprint 4)。

## 3. 主要画面

### M-01 ホーム(本人)

```
┌──────────────────────────────┐
│ 11月9日(月)                  │
│ 今日の自宅の食事               │
│  朝ごはん   ✓ 記録しました     │
│  昼ごはん   デイサービス(記録しません)│
│  夕ごはん   まだ記録していません│
│                               │
│ 記録済みの自宅食事の推定摂取量 │
│  420 kcal                      │
│  ※ 記録した朝ごはんだけです。推定で、 │
│    実際とは差があります         │
│                               │
│ ┌──────────────────────────┐ │
│ │   ごはんを記録する         │ │ ← 56px 以上
│ └──────────────────────────┘ │
│ [体の測定を記録]  [これまでの記録] │
└──────────────────────────────┘
```

- 合計の下に、何が含まれているか(何食分か、デイサービス分を含まないこと)を必ず文で示す。
- 未記録の区分が1つでもある日は「1日の合計」という語を使わない。

### M-02 いつ食べたか

1. 「いつの食事ですか?」→ [今日] [昨日] [ほかの日](遡及可能期間は D-30)
2. 「どの食事ですか?」→ [朝ごはん] [昼ごはん] [夕ごはん] [間食]
3. 「どこで食べましたか?」→ **[自宅]** のみ選べる。下に「デイサービスで食べた食事は記録しません」→ [デイサービスで食べた] を押すと記録状況に `dayservice` を付けて終了。[食べなかった] で `skipped` を付けて終了。
4. 時刻はおおよそ(任意)。省略時は区分のみ(精度=区分)。

### M-05 食べたものと量の確認

```
┌──────────────────────────────┐
│ [写真]                         │
│ AI の推定です。違っていたら直してください │
├──────────────────────────────┤
│ ごはん                 [変える]│
│ 量:お茶わん 1 杯(150 g)      │
│   [少なく −]  [多く +]         │
├──────────────────────────────┤
│ 焼き魚(さけ)         [変える]│
│ 量:1 切れ(80 g)              │
│   [少なく −]  [多く +]         │
├──────────────────────────────┤
│ [+ 食べたものを足す]  [× 消す] │
├──────────────────────────────┤
│        [ 次へ ]                │
└──────────────────────────────┘
```

- 量は「お茶わん1杯」など目安単位と g を併記(目安単位マスターの要否 D-19)。−/+ は 10% 刻み(仮)。
- AI の推定値(提供量)は内部に保持し、画面では「最初の推定:180 g」と小さく表示(修正前後が分かるように)。
- 照合できなかった食品は「どれに近いですか?」と候補を大きなボタンで提示。

### M-06 どれくらい食べたか

```
ごはん(150 g)
 [ 全部 ] [ ほとんど ] [ 半分 ] [ 少し ] [ 食べなかった ]
                    [細かく選ぶ(10%ごと)]
```
- 「全部まとめて同じ」ボタンで全明細に一括適用。
- 選んだ割合と摂取量(g)、推定 kcal を表示。

### M-07 確認して保存

- 食べた日時・区分・場所(自宅)、各食品の提供量・食べた割合・摂取量、推定合計を表示。
- 代理入力の場合は「〇〇さんの記録として、スタッフ △△ が入力します」と表示。

### M-09 記録の一覧

- カレンダー:各日を朝/昼/夕の3マスで表示(✓ 記録、ー 食べなかった、デ デイサービス、空白 未記録)。記号と文字で区別(色だけにしない)。
- 日の詳細:記録された食事と、記録状況付きの推定合計。
- 推移グラフ(任意表示):全区分が埋まった日は実線の点、未記録を含む日は白抜きの点+「一部のみ」表示。平均値は全区分が埋まった日だけで計算し、対象日数を表示。

### M-11 InBody を記録

- 項目ごとに1画面(体重 → 骨格筋量 → 体脂肪量 → 体脂肪率 → 測定日時 → 機種)。InBody の結果用紙の並びに合わせる(機種確認後に調整 D-12)。
- 範囲外はエラー、整合性のずれは警告(保存は可)。

### M-12 体の変化

- 指標の切替ボタン、期間(1/3/6/12 か月)、折れ線グラフ+下に数値表(表だけの表示にも切替可)。前回差は数値のみ。

### M-13 担当スタッフに見せる情報

```
担当:山田 さん(スタッフ)
 食事の記録を見る          [見せる ●]
 食事を代わりに記録する    [任せない ○]
 体の測定を見る            [見せる ●]
 体の測定を代わりに記録する [任せる ●]
```
- 変更時の確認文:「山田さんは、これから食事の記録を見られなくなります。すでに見た内容は取り消せません。」
- 「見せなくても、このアプリやデイサービスの利用には影響しません」を常に表示。
- 履歴(いつ・何を・どう変えたか)。

### T-01 担当利用者ダッシュボード(スタッフ)

| 列 | 内容 | 必要なスコープ |
|---|---|---|
| 利用者名 | 表示名 | 担当割当 |
| 同意 | 付与されているスコープのバッジ | 担当割当 |
| 直近7日の食事記録 | 3区分×7日のマス(記録状況のみ) | meals:read |
| 最終の食事記録日 | | meals:read |
| 最新 InBody | 測定日、体重・骨格筋量と前回差(数値のみ) | body:read |

- スコープがない列は「—(同意なし)」と表示し、データを取得しない。
- 並び替えは名前・最終記録日のみ。体重変化での並び替えや色付けはしない(評価・アラートに当たるため、D-15)。
- 詳細を開くたびにサーバーで再判定。拒否時は画面上のデータを破棄して理由を表示。
- 共用端末を想定し、無操作 15 分(仮)で自動ログアウト。

### M-14 データの書き出し・削除

- 書き出し:ボタン1つで JSON(+CSV)をダウンロード。
- 削除:説明 → 再ログイン → 確認入力 → 実行。保持されるもの(仮名化した監査ログ、バックアップの保持期間)を明示。高齢者の誤操作を防ぐため、スタッフ同席での実施を案内する案 **[未決 D-10]**。
