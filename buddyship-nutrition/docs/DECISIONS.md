## 0. v1(スタジオ向け)から v2.0(デイサービス向け)への主な変更

| 項目 | v1 | v2.0 |
|---|---|---|
| 対象 | スタジオ利用者 | リハビリ特化型デイサービス利用者(高齢者を想定) |
| 食事の範囲 | 全食事 | **自宅の食事のみ**(`location = 'home'` を DB で強制)。デイサービスの食事は対象外 |
| 食事の入力者 | 本人のみ | 本人+同意済み担当スタッフ(代理入力) |
| 同意スコープ | 食事閲覧・InBody 閲覧・InBody 入力 | **食事閲覧・食事入力・InBody 閲覧・InBody 入力**(書き込みはデータ種別ごとに個別同意) |
| 量 | 重量のみ | **AI 推定提供量 / 確認後の提供量 / 食べた割合 / 摂取量** を分けて保存 |
| 日時 | 食事日時 | **摂取日時と登録日時を分離**、摂取日時の精度を保存 |
| 欠測 | なし | **記録状況(記録/食べなかった/デイサービス/未記録)**、未記録を 0 扱いしない |
| 管理者 | 既定で健康データを見ない(未決) | **健康データの包括閲覧権限なし(確定)** |
| UI | 一般 | **高齢者向け**(大きな文字・ボタン、ウィザード、平易な言葉) |
| 運用 | — | **バックアップ・復元**を要件化 |

## 3. セキュリティリスク

1. **公開リポジトリと GitHub Pages(D-00)**:現状の設定では `main` の全ファイルが公開される。
2. **同意の自由意思**:担当スタッフとの関係で断りにくい。同意しなくてもサービス利用に影響しないことを画面と説明で明示。
3. **同意能力**:認知機能が低下した利用者の同意の有効性。Phase 1 は本人が同意できる方に限定する案(D-26)。
4. **撤回の限界**:撤回後の新規アクセスは拒否できるが、撤回前に見た情報は取り消せない。説明文に明記。
5. **共用端末**:事業所のタブレットを複数スタッフ・利用者が使う。MFA、短い無操作タイムアウト、ログアウト時のキャッシュ消去、利用者データのオフライン保存禁止。
6. **代理入力のなりすまし・誤入力**:スタッフが別の利用者に入力する誤り。入力確認画面で利用者名を大きく表示、入力者と情報源を記録、本人画面で「スタッフ入力」を表示。
7. **画像の写り込み**:自宅の写真に家族・住所が分かる郵便物・薬袋(病名が推測される)が写る。EXIF 除去、短期削除、撮影時の注意表示、AI には食事の解析のみ指示。
8. **AI プロバイダへの送信**:画像が外部(海外の可能性)に送られる。契約・保持期間の確認と、利用者への説明・同意(D-01, D-20)。
9. **管理者権限**:健康データは見えないが、割当とロールを操作できるため、管理者が自分をスタッフにして担当になれば見られる。→ **割当の変更は監査し、自分自身への割当を禁止する案**、管理者を 2 名以上にして相互確認。
10. **ビュー・定義者関数での RLS すり抜け**:カタログ検査テストで防止。
11. **バックアップ内の削除済みデータ**:保持期間中は残る。プライバシーポリシーに明記し、復元時の再削除手順を用意。
12. **service role キー漏えい**:Edge Function Secrets のみ、参照箇所の CI 検査、ローテーション手順。
