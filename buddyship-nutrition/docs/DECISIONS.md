## 2. 技術的リスク

| ID | リスク | 影響 | 対策 |
|---|---|---|---|
| R-01 | 写真 1 枚からの重量推定は本質的に誤差が大きい(器の大きさ・盛り方・隠れた具材・油) | 推定 kcal の大きな誤差 | 「推定値」表示、利用者修正を前提にした UI(重量の ± ボタン、よく使う量のプリセット)、精度の実測と開示 |
| R-02 | AI の食品名と成分表の正式名(「こめ［水稲めし］精白米 うるち米」等)が一致しない | 照合失敗・誤照合 | 別名辞書、料理マスター、候補を複数提示、照合結果のログ(ラベルと選択結果)で辞書を育てる |
| R-03 | Edge Functions(Deno)での画像デコード・検証。メモリ・CPU 時間の制限 | 検証できない / タイムアウト | 端末で縮小済み(≤1600px、≤5MB)を前提に、ヘッダ解析のみで寸法を取得する軽量実装を Sprint 2 冒頭で技術検証。不足なら検証専用の別ランタイムを検討 |
| R-04 | AI の応答時間と Edge Function の実行時間制限 | 解析の失敗 | タイムアウト 30 秒・再試行 1 回、失敗時は手入力へ。Supabase の制限値を Sprint 2 で確認 |
| R-05 | 依存の版が新しい(Vite 8、React 19.3、Tailwind 4、zod 4、TypeScript 6/7 の分岐) | 組合せの不具合 | Sprint 1 で雛形を作り、ビルド・テスト・lint が通る組合せを確認してから固定。TypeScript は typescript-eslint の対応範囲に合わせ 6.0 系 |
| R-06 | RLS / 認可関数の性能 | 遅延 | 試験規模では問題になりにくい。索引(user_id, 日時)と `(select auth.uid())` 記法、`EXPLAIN` で確認 |
| R-07 | 拒否時の監査ログ:PostgreSQL では例外を投げると同一トランザクションの INSERT が取り消される | 拒否が記録されない | 拒否時は例外を投げずエラーコードを返す方式、または Edge Function 側で記録する方式を Sprint 1 で検証 |
| R-08 | iOS の PWA 制約(ホーム画面起動時のカメラ挙動、ストレージ削除、更新の反映) | 使い勝手 | 実機確認、Service Worker の更新通知、データはサーバーに保存 |
| R-09 | AI モデルの廃止・仕様変更 | 解析停止 | モデル ID を設定値で固定、アダプタ層、廃止予定の監視 |

## 3. セキュリティ上の懸念

1. **公開リポジトリと GitHub Pages(D-00)**:現在の Pages ワークフローはリポジトリ全体を公開する。設計文書(RLS 設計・関数名)やソースが公開されても安全な設計にしているが、意図せぬ公開は避けるべき。別リポジトリ(非公開)を推奨。
2. **同意の自由意思**:トレーナーと会員の関係上、同意を断りにくい。同意しなくてもサービスを使えること、いつでも撤回できることを画面と説明文で明示する。
3. **撤回の「即時性」の範囲**:撤回後の新規アクセスは即時に拒否できるが、スタッフが**撤回前に表示・記憶・撮影した情報は取り消せない**。説明文で明示する。
4. **スタジオの共有端末**:スタッフが共用 PC/タブレットを使う可能性。MFA、短いセッション、ログアウト時のキャッシュ消去、自動ログアウト(仮:30 分無操作)。
5. **画像に写り込む情報**:顔・同席者・レシート・場所。端末で EXIF 除去、短期削除、AI には食事の解析のみを指示。撮影時の注意を表示。
6. **AI プロバイダへのデータ送信**:画像が外部(海外の可能性)に送られる。保持期間・学習利用・契約の確認と、利用者への明示的な説明・同意(D-01, D-20)。
7. **ビュー経由の RLS すり抜け**:PostgreSQL のビューは既定で所有者権限で実行されるため、RLS を回避し得る。ビューは `security_invoker = true` を必須とし、テストで検査。
8. **SECURITY DEFINER 関数の誤用**:`search_path` 未固定や引数の信頼で権限昇格につながる。共通テンプレートとカタログ検査テストで防ぐ。
9. **メールアドレスの列挙**:ログイン・招待の応答で登録有無が分からないようにする。
10. **管理者権限の集中**:管理者 1 名の端末侵害で全スタッフ割当を操作され得る。管理者 MFA 必須、管理操作の監査、管理者を 2 名以上にして相互確認。
11. **Service Role キーの管理**:Edge Function の Secrets に限定。漏えい時のローテーション手順を事前に用意。
12. **バックアップ内の削除済みデータ**:アカウント削除後もバックアップには一定期間残る。保持期間をプライバシーポリシーに記載。
