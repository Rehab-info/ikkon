# YOKU ロードマップ

ベータ版には、下記の将来機能を**先行実装しない**(指示書 12)。各項目は、ベータでの検証結果と安全設計の条件がそろってから検討する。

## 0. ベータの検証(次の段階)

- 少人数の成人カップル・ひとり利用者でのユーザビリティテスト(端末実機:iPhone Safari / Android Chrome)
- 仮説 H1〜H4(PRODUCT_REQUIREMENTS.md)のインタビュー。アプリ内で利用状況は収集しないため、任意のアンケートで行う
- VoiceOver / TalkBack での実機確認
- 「YOKU 科学的根拠・独立監査統合版 Ver.3.0」との突き合わせ

## 1. ベータ中に入れられる改善(個人利用の範囲)

| 項目 | メモ |
|---|---|
| 書き出しファイルの読みこみ(復元) | 機種変更のため。読みこみ時の検証・重複処理・スキーマ移行が必要 |
| 端末内データの暗号化 | パスフレーズ+WebCrypto(PBKDF2/AES-GCM)。忘れたら復旧できないことを明示。ロック画面とセット |
| Wellness の1日複数回の記録 | 時刻つきの記録に変える場合は version(2) で移行 |
| 公開(GitHub Pages など HTTPS) | Pages ワークフローにビルドを追加。公開は承認後 |
| iOS Safari・Firefox の E2E | Playwright の WebKit / Firefox |

## 2. 将来の拡張(指示書 12。ベータ検証後に判断)

| 拡張 | 前提条件(安全設計) |
|---|---|
| パートナーアカウント連携 | 双方の明示的な同意、いつでも解除、解除したことを相手に強く通知しない設計の検討、DV 懸念時の即時退出 |
| 双方向の選択的共有 | 監査結果 8 の条件:双方向かつ対称、生データではなく粗い段階、いつでも撤回・非表示、事前プレビュー、性欲項目は既定で非共有 |
| ふたりの Food お気に入り | 低機微。最初の連携機能の候補 |
| 共有された感謝メッセージ | 既読・返信の催促を作らない |
| 双方が自発的に公開した好みの確認 | 一致の表示が「同意」と誤解されない文言。片方だけの公開で相手に通知しない |
| 安全なプライベートメッセージ | エンドツーエンド暗号化が前提。既存のメッセージアプリとの役割分担を検討 |
| AI による一般的な対話支援 | 記録を外部 AI に送らない構成を優先(端末内モデル)。送る場合は送信内容・送信先の明示と都度の同意(Apple 5.1.2(i) 等) |
| 有料プラン | 個人の記録を広告・データ販売に使わないことを前提に |

サーバーに記録を保存する段階では、同意の設計(取得時・提供時)、撤回、保存期間、暗号化、侵害時の対応、JIS Q 15001・民間 PHR 指針の推奨水準、医療機器プログラム該当性を、専門家と確認する。
