# YOKU プライバシーとセキュリティ

YOKU は性的な好みや親密な体験を扱うため、通常のメモアプリ以上の配慮を前提に設計した。特に、**パートナーによる監視・強要・支配的行動への悪用**を想定している。

## 1. 基本方針

1. 記録はすべて端末内(IndexedDB)。サーバー・アカウント・同期はない。
2. すべての記録は初期設定で非公開。
3. 共有は毎回、本人が「選ぶ → 文章を編集 → プレビュー → 共有/コピー」を行ったときだけ。
4. 性的な記録を自動同期しない。相手のデータを受け取らない。
5. 相手に共有を要求する機能・催促・既読・共有履歴はない。
6. 記録の有無を相手に通知しない。通知機能そのものがない(ロック画面に内容が出ることはない)。
7. 外部 AI へ記録を送らない。広告 SDK・追跡 SDK はない。
8. 書き出しと全削除ができる。
9. 共有した内容は相手の端末から削除できないことを、共有の確認画面・全削除の画面・プライバシー画面で説明する。

## 2. 要件と実装・検証

| # | 要件 | 実装 | 検証 |
|---|---|---|---|
| 1 | 初期設定で非公開 | 共有の選択は初期状態で何も選ばない(Food/Thanks は本人が開いた記録だけ選択済み) | RTL「Intimacy:初期状態で何も選ばれておらず…」 |
| 2 | 毎回明示的な操作 | 4ステップ。Intimacy は「内容と送り先を確認しました」にチェックしないと共有・コピーのボタンが押せない | RTL・E2E |
| 3 | 自動同期しない | 通信コードがない。CSP `connect-src 'self'` | 静的監査・E2E 通信監査・CSP テスト |
| 4 | 共有の要求機能なし | 該当機能なし | 要件レビュー |
| 5 | 記録の有無を通知しない | 通知 API を使っていない | 静的監査(Notification・showNotification を禁止) |
| 6 | ロック画面に性的な内容を出さない | 通知なし。アプリ切替画面ではアプリを覆う(設定、既定オン)。ページタイトルは常に「YOKU」 | 手動確認 |
| 7 | 外部 AI に送らない | 該当機能・通信なし | 静的監査 |
| 8 | 広告・追跡 SDK なし | 本番依存は react / react-dom / dexie / dexie-react-hooks / recharts / lucide-react だけ | 静的監査(依存関係の一覧を固定) |
| 9 | 削除とエクスポート | 設定から | RTL・E2E |
| 10 | 共有後は削除できないことの説明 | 共有のプレビュー画面・全削除ダイアログ・プライバシー画面 | RTL |

## 3. 共有文の混入防止

共有文の下書きは `src/lib/share.ts` の純粋関数だけで作る。下書きに入るのは次だけ:

| 種類 | 入るもの | 入らないもの |
|---|---|---|
| Intimacy | 選んだ好み・境界線の**名前とステータス**、決まった前置きと結び | メモ、タグ、良かった体験の記録(選択肢にも出さない)、更新日 |
| 今日の気持ち | 選んだ言葉と、本人がその場で書いたひとこと | Wellness の数値すべて |
| Food | 料理名、店名 | 写真、場所、誰と食べたか、美味しかったポイント、メモ |
| Thanks | 「伝えたいメッセージ」(空なら「何に感謝しているか」) | そのときの気持ち、相手の名前 |
| 対話テーマ | 選んだテーマ | — |

| もう一度お願いしたい | 本人が確認した「呼び方」(初期値は記録の名前)とテンプレート文、任意の結び | メモ、タグ、体験の詳細(心地よかったこと・うれしかったこと・また希望すること・自由記述)、ほかの好み・境界線・体験 |

`navigator.share` には `text` だけを渡す(URL・タイトル・ファイルを付けない)。共有シートがない環境ではクリップボードへコピーする。
写真は共有しない。仮に将来共有する場合も、保存されている写真は再エンコード済みで EXIF を含まない。

テスト:`src/lib/share.test.ts`(秘密の文字列を各欄に入れ、下書きに出ないことを確認)、`src/App.test.tsx`、`e2e/flows.spec.ts`(実際にコピーされた文字列を検査)。

## 4. 悪用(監視・強要・支配)への配慮

| 想定 | 設計 |
|---|---|
| 相手が端末をのぞく | Intimacy を下部ナビに置かない。一覧はぼかし表示(既定オン、タップで表示)。ホームの最近の記録は「親密さの記録」とだけ表示。Intimacy を丸ごと非表示にできる(データは残る) |
| 相手がアプリ切替画面を見る | 背面に回るとアプリを覆う(既定オン)。ブラウザー・OS によっては効かない |
| 「見せて」「共有して」と強いられる | 共有の要求・催促・既読・共有履歴の機能がない。アプリ内に「相手が見られる場所」がない |
| 過去の記録を同意の根拠にされる | 「過去の記録や好みの一致は今の同意を意味しない」を Intimacy の冒頭・プライバシー画面に表示。ステータスは「今の気持ち」で、共有文の結びに「変わることもある」。同意を判定する機能はない |
| 相手の技術や身体を評価させる | 点数・ランキング・評価の項目はない |
| 急いで記録を消したい | 設定 → すべての記録を削除(「削除」と入力して確定)。相談窓口(DV相談ナビ #8008、DV相談+)をプライバシー画面に記載 |
| 書き出したファイルが見られる | 書き出し前に「暗号化されていない」「クラウドの自動同期フォルダに注意」と表示 |

## 4-A. 「もう一度お願いしたい」の同意に関する要件

| 要件 | 実装 |
|---|---|
| 共有するかは毎回本人が決める | 作成画面に入っても何も送られない。確認のチェックは毎回オフから |
| 共有前に必ずプレビュー | 確認画面を経ないと共有・コピーのボタンが出ない |
| 過去に良かったことが今も望まれているとは限らない | 確認画面で明示。「今は希望しない」「苦手・避けたい」の好みからは作れない |
| 希望の共有は同意を意味しない/アプリは同意を判定しない | 案内文を詳細・作成・確認画面に表示。同意・反応を入力・判定する UI やデータがない |
| 相手が断る自由 | 結びの一文(既定オン)、「相手には断る自由があり、返事がなくても大丈夫」 |
| 催促・再送要求・既読監視なし | 該当機能なし。完了画面で「返事を待ったり、催促したりする必要はありません」 |
| 相手の義務として表示しない/応じなかったことを記録・採点しない | 共有の記録・反応の記録を持たない |
| 他の Intimacy 記録の混入なし | 下書きは `buildRequestMessage(呼び方, トーン)` だけで作る(テストで全欄に秘密の文字列を入れて確認) |

## 5. セキュリティ

| 項目 | 内容 |
|---|---|
| CSP | 本番ビルドの `index.html` に `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'; frame-src 'none'` など。`style-src 'unsafe-inline'` はグラフ等のインラインスタイルのため(スクリプトは不可) |
| XSS | React のテキスト描画のみ。`dangerouslySetInnerHTML`・`innerHTML`・`eval`・`new Function` は使わない(静的監査)。`<img onerror>` や `<script>` を入力しても実行されないことを RTL で確認 |
| Referrer | `<meta name="referrer" content="no-referrer">` |
| 検索エンジン | `noindex, nofollow` |
| 外部リソース | Web フォント・CDN・解析タグを読みこまない。Service Worker は自分のファイルだけをキャッシュ(実行時の外部キャッシュ設定なし) |
| 依存関係 | 本番の依存は6つに固定(テストで検査)。`npm audit` の指摘は開発用ツール(vitest・workbox-build)のみで、配布物には含まれない |

## 6. できないこと(限界)

- **保存データは暗号化していない。** 端末のロックを解除できる人は、ブラウザーの開発者ツール等で IndexedDB の中身を読める可能性がある。
- **アプリ内ロック(PIN)はない。** ブラウザーだけで動く PIN は、端末を操作できる人に対して強い保護にならず(開発者ツールで回避できる)、忘れた場合の復旧もできないため、誤った安心感を与えないようベータでは実装しなかった。端末の画面ロックを使うよう案内している。
- ぼかし・アプリ切替時の目隠しは「のぞき見を減らす」もので、確実な保護ではない。
- ブラウザーの容量不足やデータ削除で記録が消えることがある(設定から「消さないよう頼む」= `navigator.storage.persist()` を申請できる)。
- 共有した文章は、相手の端末・メッセージアプリ・そのバックアップに残る。
- OS の共有シートやクリップボードの扱いは OS・アプリに依存する(クリップボード履歴・同期機能など)。

## 7. 法令について(一般的な整理。専門家の確認が必要)

監査結果のとおり、日本の個人情報保護法で「性生活」は要配慮個人情報に列挙されていない(GDPR の特別カテゴリー・JIS Q 15001 の機微情報とは異なる)。また本人が明示的に操作して相手に伝える設計は、法令で禁止されていない。
ただし YOKU ベータは事業者がデータを取得しない(端末内のみ)。将来サーバー同期・アカウント連携を行う場合は、取得時・提供時の明示的同意、撤回の容易さ、提供先の明示、JIS Q 15001 や民間 PHR 事業者向け指針(総務省・厚生労働省・経済産業省)の推奨水準、医療機器プログラム該当性(厚生労働省ガイドライン)を、弁護士等の専門家と確認すること。
