# YOKU ベータ版 要件定義

版:0.1.0-beta(2026-11-08)/ 対象:成人(18歳以上)

## 1. コンセプト

- ブランドメッセージ:「自分を知る。ふたりをもっと知る。」
- 欲求を管理・採点しない。自分を理解し、好きなこと・うれしかったこと・感謝を、伝えたいときに伝える。
- 4領域(Wellness / Intimacy / Food / Thanks)はすべて**ひとりで使っても成立**する。パートナー共有は任意の追加機能。
- 性的な好みと過去の体験はセンシティブな個人情報として扱い、共有を強制しない。
- 機微性の異なる情報を同じ公開設定で扱わない(下の「機微性の段階」)。

## 2. 科学的根拠と製品設計の区別

参照資料:「YOKU検証レポート 独立監査結果」(2026-11-07、Google ドライブ)。指示書にある「科学的根拠・独立監査統合版 Ver.3.0」そのものはリポジトリ・ドライブで見つからなかったため、統合の元になった監査結果を参照した(KNOWN_LIMITATIONS.md)。

監査結果から製品に反映したこと:

| 監査の指摘 | 製品での扱い |
|---|---|
| 睡眠不足と食欲の関連は主要文献が概ね妥当 | Wellness で項目ごとの推移を見せる。ただし表示は「関連」までで、原因の判断はしない(画面に明記) |
| 観察研究を「因果」と書かない | アプリ内の文言は「関連」「目安」に統一。改善効果を表示しない |
| Kalmbach(睡眠時間)と Kling(睡眠の質)の食い違い | 睡眠時間と「睡眠の休息感」を別々に記録 |
| 単一項目 EMA の妥当性に出典がない/既存尺度の改変は妥当性を失う | 0〜10 は「主観的な目安」とし、既存尺度(KSS・PSQI 等)の名前を使わない。合算スコアを作らない |
| パートナーへの性欲の生データ共有は慎重に(ただし「法的禁止」は誤り) | 根拠を「法令」ではなく「関係性リスクと悪用リスクを踏まえた設計判断」とする。Wellness の数値は共有文に入れず、「今日は話したい/そっとしておいてほしい」等の粗い言葉で伝える |
| 共有は双方向・撤回可能・事前プレビュー・性欲は既定で非共有・DV 懸念時の窓口 | ベータは一方向の手動共有のみ。毎回プレビューと明示操作。性的な内容は既定で非公開。プライバシー画面に相談窓口と全削除を案内 |
| 「特に女性」など根拠のない性別限定 | 性別で文言を変えない。性別を入力させない |
| 「性生活」は個人情報保護法の要配慮個人情報ではない | 法的分類に頼らず、機微な情報として最大限の配慮で設計する(PRIVACY_AND_SECURITY.md) |

**Intimacy・Food・Thanks の記録・共有機能は、科学的に効果が実証された機能ではない。** ユーザーニーズを検証するための新規プロダクト仮説として扱い、関係満足度・性的満足度・健康の改善をアプリ内で表示・示唆しない(設定画面「このアプリについて」に明記)。

### 検証したい仮説(ベータ)

- H1:欲求と心身の状態を合算せず項目別に記録すると、自分の状態の理解に役立つと感じる人がいる
- H2:性的な好みを「今の気持ち」として整理する場があると、話すきっかけを作りやすい
- H3:美味しかった食事の記録は、ふたりの次の予定(また行きたい)を作るきっかけになる
- H4:感謝を記録しておくと、伝えるハードルが下がる(伝えなくても責められない)
- いずれも、ベータの利用者インタビューと任意のアンケートで確かめる(アプリは利用状況を収集しない)

## 3. 機微性の段階

| 段階 | 対象 | 既定 | 共有文に自動で入るもの |
|---|---|---|---|
| 高 | Intimacy(好み・体験・境界線) | 非公開、一覧はぼかし表示、ホームに内容を出さない | 本人が選んだ項目の**名前とステータス**だけ。メモ・タグ・体験の記録は入らない。送る前に「機微な情報が含まれます」の確認が必須 |
| 中 | Wellness(特に性欲) | 非公開。性欲項目は非表示にできる | 数値は入らない。気持ちを言葉で選ぶ |
| 低 | Food・Thanks | 非公開 | 料理名・店名/感謝の「伝えたいメッセージ」。メモ・同行者・場所・写真・気持ちの欄は入らない |

## 4. 画面構成

```
初回:成人確認 →(はじめる | デモ)
ホーム
 ├ 今日の日付・今日の自分の状態・今日の記録への導線
 ├ 4領域カード(Intimacy は表示設定がオンのときだけ)
 ├ パートナーへ伝えたいこと(まだ伝えていない感謝・また食べたいもの)
 └ 最近の記録(Intimacy は「親密さの記録」とだけ表示)
Wellness:今日 / 推移(項目・7日/30日・表で見る)/ これまでの記録(編集・削除)
 └ 記録:日付・三大欲求・心身の状態・睡眠時間
Intimacy:タブ(好み / 良かった体験 / 境界線)
 ├ 好み:分類・名前(自由入力)・ステータス5段階・タグ・メモ
 ├ 良かった体験:日付(任意)・タイトル・心地よかったこと・うれしかったこと・また希望すること・自由記述(点数なし)
 └ 境界線:内容・4つの気持ち(好き/相談したい/希望しない/決めていない)
Food:検索・すべて/お気に入り/また食べたい・ジャンル・月ごとの履歴
 └ 記録:料理名・日付・ジャンル・店名・場所(手入力)・写真・美味しかったポイント・また食べたい・お気に入り・誰と・メモ
Thanks:テンプレート・自由入力・月ごとのふりかえり
 └ 記録:日付・相手・何に感謝・そのときの気持ち・伝えたいメッセージ・「伝えた」(本人の任意)
Together:今日伝えたい気持ち / 好みについて話す / また食べたいもの / ありがとう / ふたりの対話テーマ
 └ 共有:1.選ぶ → 2.文章を編集 → 3.プレビュー(と機微情報の確認)→ 4.共有シート or コピー
設定:表示(性欲項目・Intimacy・ぼかし・アプリ切替時の目隠し・テーマ)/ プライバシー / 保存容量 / 書き出し / 全削除 / デモ
```

下部ナビは「ホーム・Wellness・Food・Thanks・Together」。**Intimacy は下部ナビに置かない**(画面をのぞかれたときに目立たせない)。ホームと Together から開く。

## 5. 必須機能の対応表

| 指示書 | 実装 |
|---|---|
| 5-1 ホーム | `features/home/HomePage.tsx` |
| 5-2 Wellness:0〜10・任意回答・欠測と0の区別・性欲非表示・7/30日の個別グラフ・合算スコアなし | `features/wellness/*`。0〜10 はスライダーではなく 11 個の選択肢(初期位置で回答を誘導しない)。未選択=未回答 |
| 5-3 Intimacy A〜E | `features/intimacy/*`、共有は `features/share/SharePage.tsx` |
| 5-3「以前好きだった ≠ 現在」 | ステータスは常に「今の気持ち」として上書き。最終更新日を表示し、90日以上見直していない項目に「今の気持ちと合っていますか?」を表示。共有文の結びに「これは今の気持ちで、変わることもある」 |
| 5-3 同意 | 「過去の記録や好みの一致は今の同意を意味しない」を Intimacy の冒頭・プライバシー画面に表示。同意の判定機能はない |
| 5-3 共有履歴・既読・要求・催促 | 実装しない |
| 5-4 Food・写真の圧縮/容量制限/削除/メタデータ除去・位置の自動取得なし | `features/food/*`、`lib/image.ts`、`db/repo.ts` |
| 5-5 Thanks・テンプレート6種・未送信を責めない・回数で採点しない | `features/thanks/*`。件数や連続記録日数は表示しない |
| 5-6 Together | `features/together/TogetherPage.tsx`。共有の記録は持たない |
| 5-7 設定とプライバシー | `features/settings/*`。アプリ内ロック(PIN)はベータでは実装しない(理由は KNOWN_LIMITATIONS.md) |
| 8 デモモード | `db/demo.ts`(Wellness 30日分・未回答を含む、Intimacy、Food、Thanks)。別データベース `yoku-demo` |

## 5-A. Intimacy 追加機能「もう一度お願いしたい」(Ver.4.1)

目的:口では伝えにくい好みや、心地よかったことを、穏やかに伝えて**相談を始めるきっかけ**をつくる。性的行為への同意を取得・判定するものではない。

| 項目 | 内容 |
|---|---|
| 入口 | 好みの詳細(体位・プレイ・また体験したいこと、かつ今の気持ちが「今は希望しない」「苦手・避けたい」ではないもの)、良かった体験の詳細 |
| 詳細画面の導線 | もう一度お願いしたい ♡ / 共有メッセージを作成(既存の Together 共有へ、この項目を選んだ状態で)/ 好みを編集(体験は「記録を編集」) |
| 画面 | `#/intimacy/request?preference=<id>` または `?memory=<id>`。1.文章をつくる → 2.確認 → 3.送る |
| テンプレート | やさしく伝える / 少し照れながら / 相談したい / シンプルに(`src/lib/request.ts`)。切り替えると文章を作り直す。送る前に自由に編集可 |
| 〇〇 | 「伝えるときの呼び方」。記録の名前が初期値で、本人が書き直せる。メモ・タグ・体験の詳細・ほかの記録は入らない |
| 返事のしやすさ | 既定で末尾に「無理に答えなくて大丈夫。気が向いたら相談できたら嬉しいな。」(外せる) |
| 確認画面 | 共有するプレイの名称 / 送信する文章 / 共有先は自分で選ぶ / 相手の端末に残る / 以前よかったことが今も望まれているとは限らず、相手には断る自由がある / 案内文 / 「内容と送り先を確認しました」にチェックするまで送れない |
| 共有 | Web Share API(文章だけ)またはコピー。共有シートを閉じたら「何も送られていません」と表示し確認画面にとどまる |
| 保存 | 下書きは画面の状態だけ。IndexedDB に共有文・共有履歴・相手の反応を保存しない(新しいテーブルなし) |
| 相手の反応 | ベータでは取得・通知・判定しない。将来の設計案は ROADMAP.md |
| 案内文 | 「これは希望を伝えるメッセージです。実際にするかどうかは、お互いの気持ちを確認して決めましょう。」(詳細・作成・確認の各画面) |

「今は希望しない」「苦手・避けたい」の好みには入口を出さず、URL を直接開いても文章を作らない(以前好きだったことを今の希望とみなさない)。

## 6. ベータでやらないこと

サーバー同期、ユーザー認証、外部 AI、広告・行動解析 SDK、決済、プッシュ通知、パートナーアカウント連携、相手データの受信、共有履歴。将来の検討は ROADMAP.md。
