# 設計書 — MIND BUY プロトタイプ

> 中心理念：**肩書きではなく、アイデアを通じて人の可能性を発見する。**
>
> 本書はプロトタイプ実装前に作成した設計です。サービス名は「MIND BUY」です（当初は仮称「IDEA PLATFORM」）。表記は `src/config/brand.ts` の1か所で変更できます。

---

## 1. サイトマップ

```
/                         トップページ
├─ /ideas                 アイデア一覧（検索・カテゴリー・並び替え）
│   └─ /ideas/:id         アイデア詳細（購入前に公開できる範囲のみ）
│       └─ /checkout/:id  購入確認デモ（決済なし）
├─ /creators/:id          創作者プロフィール
│   └─ /connect/:creatorId  相談申請（送信はローカルのデモ）
├─ /workspace             知識創造ワークスペース（知識マップ・メモ・情報ソース・仮説/反証・構造化）
│   └─ /workspace/iip/:id IIP（アイデア情報パッケージ）作成・プレビュー・出品審査申請デモ
├─ /account               マイページ（保存・購入デモ・出品デモ・相談申請・受信した相談・プロジェクト・バックアップ）
├─ /admin                 運営管理画面（デモ：本番の認証・認可なし）
└─ /notice                プロトタイプについて（本番未対応事項の一覧）
```

## 2. 主要ユーザーフロー

### A. 購入者：発見 → 理解 → 購入デモ
1. トップ「アイデアを探す」→ `/ideas`
2. キーワード検索・カテゴリー絞り込み・並び替え → アイデアカード
3. `/ideas/:id` で課題・想定顧客・差異・検証状況・納品物・サンプル知識マップを確認（核心情報は非表示）
4. 「購入手続きへ（デモ）」→ `/checkout/:id`
5. 利用条件の確認チェック（すべて必須）→「購入デモを実行」
6. 「これは購入体験のデモです。決済は行われていません」を表示。マイページの購入デモ履歴・運営画面に記録

### B. 購入者：アイデアから創作者へ
1. アイデア詳細の創作者カード →「プロフィールを見る」→ `/creators/:id`
2. 発想の背景・思考スタイル・アイデア制作の考え方を読む
3. 「相談を申し込む」→ `/connect/:creatorId`（対象アイデア・目的・内容・協力形態）
4. 確認ステップ → 送信デモ → ステータス「創作者の返答待ち」
5. 創作者が承諾すると「双方同意」。連絡先は同意前に一切表示しない

### C. 創作者：構造化 → 商品化
1. `/workspace` でプロジェクト作成
2. メモ・情報ソースを登録、知識マップ（8種のノード）を編集・接続
3. 仮説・反証タブで仮説ごとの根拠/反証と判定を管理
4. 構造化タブでマップから「課題/顧客/解決策/差異/根拠」を整理
5. 「IIPを作成」→ `/workspace/iip/:id` で各項目を入力、プレビュー、印刷/HTML出力
6. 「出品審査を申請（デモ）」→ 運営画面の審査一覧へ

### D. 運営：審査・管理
1. デモ利用者を「運営（デモ）」に切り替え → `/admin`
2. 出品審査（品質チェックリスト・承認/差し戻し/却下）→ 承認でアイデアが公開
3. 公開状態の変更、購入デモ履歴、相談申請と双方同意の状態、デモKPIの確認

```
│   ├─ seed.ts              初回シード・デモデータ初期化

│   └─ backup.ts            全体/プロジェクト単位のJSONエクスポート・インポートと検証
├─ ai/assistant.ts          将来のAI連携インターフェース（現状はローカルのルールベースのみ）
├─ hooks/useLiveData.ts     Dexie liveQuery を React で購読
├─ context/DemoUserContext  デモ利用者の切り替え（認証ではない）

```

## 4. データモデル（`src/types/index.ts`）

| 型 | 主な項目 | 保存先 |
|---|---|---|
| `User` | id, displayName, role(buyer/creator/admin), organization, creatorId | IndexedDB `users` |
| `CreatorProfile` | 表示名, 背景, 関心分野, 公開可能な経歴（任意）, 思考スタイル, 制作の考え方, 相談受付状態 | `creators` |
| `Idea` | タイトル, 概要, 課題, 想定顧客, 差異, 検証状況, 納品物, サンプルマップ, 価格, 公開状態 | `ideas` |
| `IdeaPreview` | `Idea` のうち購入前に表示できる項目だけを抜き出した型 | （派生） |
| `IdeaPackage` | IIP本体：各セクション本文, 連携ノード, 状態 | `packages` |
| `KnowledgeProject` | タイトル, 説明, メモ, 構造化結果 | `projects` |
| `KnowledgeNode` | 種別(8種), ラベル, 詳細, 座標, 仮説の判定 | `nodes` |
| `KnowledgeEdge` | 接続元/先, 関係(支持/反証/関連/展開) | `edges` |
| `SourceReference` | 情報ソース（Web/書籍/論文/ヒアリング/データ） | `sources` |
| `PurchaseDemo` | 購入デモ記録（決済なし・権利移転なし） | `purchases` |
| `ConnectionRequest` | 相談申請・双方同意の状態 | `connections` |
| `ReviewRecord` | 出品審査・品質チェックリスト | `reviews` |
| `ActivityLog` | 操作履歴（デモ用。本番の監査ログではない） | `activity` |

アイデアの公開状態：`draft`（下書き）/ `review`（審査中）/ `published`（公開・購入受付中）/ `nondisclosure`（非公開期間中・販売停止）/ `paused`（公開停止）/ `rejected`（却下）

## 6. デザインシステム

- **方針**：Intellectual / Minimal / Premium / Human-centered / Calm。白基調・広い余白・細い罫線。グラデーション・発光・過剰なアニメーションは使わない。
- **カラー**（`src/index.css` の `@theme`）
  - `ink`（濃紺）`#14213d`：見出し・主要ボタン
  - `charcoal` `#2e3238`：本文
  - `muted` `#5f6670`：補足（白背景でコントラスト比 4.5:1 以上）
  - `line` `#e4e6ea`：罫線 / `paper` `#f7f7f5`：面の区切り
  - `accent`（控えめな真鍮色）`#8a6a2f`：強調・ラベル（文字色として使う時もAA相当）
- **ノード種別色**：アイデア（濃紺）・課題（えんじ）・事実（スレート）・仮説（琥珀）・根拠（緑）・反証（赤茶）・解決策（青緑）・実行計画（紫）。色に加えアイコンと文字ラベルで区別（色覚多様性への配慮）。
- **タイポグラフィ**：システムの日本語フォント（ヒラギノ角ゴ / Noto Sans JP / 游ゴシック）。外部フォントは読み込まない（外部送信を発生させないため）。本文16px・行間1.8。
- **部品**：角丸は小さめ（6px）、影はほぼ使わず罫線で区切る。フォーカスリングは常に可視。
- **レスポンシブ**：〜640px で1カラム・ハンバーガーメニュー、ワークスペースはタブ切り替え。

## 7. 開発順序

1. 基盤：Vite + React + TS + Tailwind、ルーティング、共通レイアウト、デモ利用者切り替え、IndexedDB とシード
2. アイデア市場：トップ → 一覧 → 詳細 → 購入デモ → 創作者 → 相談申請
3. 知識創造アプリ：ワークスペース（React Flow）→ メモ/ソース/仮説/構造化 → 保存/復元 → IIP
4. 運営画面：審査・公開状態・購入デモ・相談/同意・KPI
5. 品質確認：型チェック・ESLint・ビルド・ユニットテスト（保存/復元）・E2E（主要導線・モバイル）・`npm audit`
