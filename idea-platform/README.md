# IDEA PLATFORM（仮称）— プロトタイプ

> **肩書きではなく、アイデアを通じて人の可能性を発見する。**

知識創造AI・アイデア／知識資産の販売・創作者マッチングを統合したWebサービスの、**ローカルで動作するプロトタイプ**です。
ブラウザだけで動き、サーバー・外部API・決済は使いません。データはブラウザの IndexedDB にのみ保存されます。

> ⚠️ **本番環境として公開しないでください。** 認証・認可・決済・契約・監査ログは実装していません（[本番化に必要な追加開発](#本番化に必要な追加開発)）。
> 登場する人物・組織・アイデアはすべて架空のデモデータです。

## 起動方法（Windows 11）

### 1. Node.js をインストール

[Node.js 公式サイト](https://nodejs.org/ja) から **LTS 版（v22 推奨。v20 の場合は 20.19 以上）** をインストールします。
インストール後、PowerShell を開き直して確認します。

```powershell
node -v
npm.cmd -v
```

### 2. 依存パッケージをインストールして起動

PowerShell でこのフォルダ（`idea-platform`）に移動して実行します。

```powershell
cd C:\path\to\ikkon\idea-platform
npm.cmd install
npm.cmd run dev
```

表示された `http://127.0.0.1:5173/` をブラウザ（Edge / Chrome 推奨）で開きます。終了は `Ctrl + C` です。

### PowerShell で `npm` が実行できない場合

`npm : このシステムではスクリプトの実行が無効になっているため…（PSSecurityException）` と表示される場合は、
PowerShell の実行ポリシーにより `npm.ps1` がブロックされています。**`npm` の代わりに `npm.cmd` を使ってください**（上記の手順はすべて `npm.cmd` で書いています）。

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run build
```

`npx` も同様に `npx.cmd` を使います（例：`npx.cmd playwright install chromium`）。
実行ポリシーそのものを変更する方法もありますが、組織のポリシーに従ってください。コマンドプロンプト（cmd.exe）を使えば `npm` のままで実行できます。

### 3. 本番ビルドの確認（任意）

```powershell
npm.cmd run build
npm.cmd run preview
```

`http://127.0.0.1:4173/` で、ビルド済みのアプリを確認できます。

### 4. E2Eテストを実行する場合（任意）

初回のみ、テスト用ブラウザをダウンロードします。

```powershell
npx.cmd playwright install chromium
npm.cmd run e2e
```

## 体験できること

ヘッダー右上（スマートフォンではメニュー内）の **デモ利用者の切り替え** で立場を変えられます。ログインではありません。

| デモ利用者 | 主な体験 |
|---|---|
| 購入者：森下 遥 | アイデアの検索・詳細確認、購入デモ、保存、創作者への相談申請 |
| 創作者：朝倉 みなと | ワークスペース（知識マップ・メモ・情報ソース・仮説/反証・構造化）、IIP作成、出品審査申請、受信した相談への返答 |
| 運営（デモ） | 出品審査（品質チェックリスト）、公開状態の変更、購入デモ・相談申請・双方同意の確認、デモKPI |

おすすめの順番：

1. 購入者で `/ideas` → 気になるアイデア → 「購入手続きへ（デモ）」
2. 同じアイデアの創作者プロフィール → 「相談を申し込む」
3. 創作者に切り替え → マイページ「受信した相談」で承諾（双方同意）
4. 創作者で `/workspace` → 知識マップを編集 → 「構造化・IIP」タブ → IIPを作成 → 出品審査を申請
5. 運営に切り替え → `/admin` の「出品審査」でチェックリストを確認して承認 → `/ideas` に公開される

## データモデル

型定義は [`src/types/index.ts`](src/types/index.ts) にあります。

| 型 | 説明 |
|---|---|
| `User` | デモ利用者（購入者・創作者・運営）。認証情報は持たない |
| `CreatorProfile` | 創作者プロフィール。資格・職歴は任意（`publicCareer?`） |
| `Idea` | アイデア（商品）。公開状態：下書き／審査中／購入受付中／非公開期間中／公開停止／非承認 |
| `IdeaPreview` | `Idea` のうち購入前に表示してよい項目だけの型。詳細画面はこの型に変換してから描画 |
| `IdeaPackage` | IIP（アイデア情報パッケージ）。9セクション＋プレビュー用ノード |
| `KnowledgeProject` | 知識創造プロジェクト（メモ・構造化結果を含む） |
| `KnowledgeNode` | 知識マップのノード（アイデア・課題・事実・仮説・根拠・反証・解決策・実行計画） |
| `KnowledgeEdge` | ノード間の関係（関連・支持する・反証する・展開する） |
| `SourceReference` | 情報ソース（URLは http/https のみ） |
| `PurchaseDemo` | 購入デモの記録（`kind: 'demo'` 固定） |
| `ConnectionRequest` | 相談申請。申請者・創作者それぞれの同意状態を保持 |
| `ReviewRecord` | 出品審査（品質チェックリスト・判定・コメント） |
| `ActivityLog` | デモ用の操作履歴（本番の監査ログではない） |

保存先：IndexedDB（Dexie）。スキーマは [`src/db/database.ts`](src/db/database.ts)。

## デモデータ

[`src/data/seed.ts`](src/data/seed.ts)。すべて架空です。

- 創作者 6人（会社員・学生・研究者・起業家・主夫・編集者）
- アイデア 8件（ヘルスケア・教育・環境・ビジネス・生活・地域・IT・文化）
  - 購入受付中 6件／非公開期間中 1件／審査中 1件
- サンプルの知識創造プロジェクト 1件、購入デモ・相談申請・審査待ちの例 各1件

マイページの「データ管理」から、初期状態へのリセット、JSONバックアップの書き出し・復元ができます。

## 既知の制約

- **データはブラウザごと**：別のブラウザ・端末・シークレットウィンドウとは共有されません。ブラウザのサイトデータを消去すると失われます（JSONバックアップを推奨）。
- **認証なし**：デモ利用者の切り替えは誰でも行えます。運営画面も誰でも表示・操作できます。
- **購入・相談・出品はデモ**：決済・メール送信・契約締結・権利移転・納品物の受け渡しは行いません。
- **AI連携なし**：ワークスペースの「点検する」はローカルのルールベースです。`src/ai/assistant.ts` の `KnowledgeAssistant` を実装すれば差し替えられます（APIキーはブラウザに置かず、サーバー側で保持すること）。
- **PDF出力は準備中**：IIPは印刷（ブラウザの「PDFに保存」も可）またはHTML出力で代替しています。
- **購入条件の文言は叩き台**：法務確認は行っていません。
- **ディープリンク**：`npm run preview` / `dev` では各URLを直接開けますが、静的ホスティングに置く場合はSPAのフォールバック設定が必要です。
- **同時編集なし**：同じプロジェクトを複数タブで同時に編集すると、後から保存した内容で上書きされます。
- **ドラッグ操作**：知識マップのノード移動・接続はタッチ操作にも対応しますが、小さな画面では操作しづらい場合があります。
- **このリポジトリについて**：このフォルダは既存の静的サイト（一献）と同じリポジトリ内に置いています。ルートの GitHub Pages ワークフローはリポジトリ全体を公開するため、このブランチを `main` にマージするとソースコードが公開対象に含まれます（ビルドはされないため、アプリとしては動作しません）。別リポジトリへの移動、またはワークフローでの除外を推奨します。

## 本番化に必要な追加開発

アプリ内の `/notice` にも同じ一覧を表示しています（[`src/content/productionGaps.ts`](src/content/productionGaps.ts)）。

**認証・認可**
- 利用者登録・ログイン（メール認証、多要素認証、パスワード再設定）
- ロールに基づく権限管理と、サーバー側での認可チェック
- 運営画面へのアクセス制限、セッション管理・CSRF対策

**決済**
- 決済代行サービスとの連携（カード情報は自社で保持しない）
- 返金・キャンセル・領収書、創作者への売上分配・振込、税務処理
- 特定商取引法に基づく表記

**契約・権利**
- 法務確認済みの利用規約・プライバシーポリシー・購入条件
- 利用許諾契約（利用範囲・非公開期間・再販売禁止）の締結フロー、同意記録の保存
- 紛争・権利侵害の申立て窓口

**個人情報・データ保護**
- サーバー側データベース・暗号化保存・バックアップ
- 同意後の連絡手段（サービス内メッセージ）と連絡先の段階的開示
- 開示・訂正・削除請求への対応、データ保持期間

**監査・運用**
- 改ざん防止された監査ログ（運営操作・審査・公開状態の変更）
- 審査の担当割り当て・二重チェック、不正利用・通報対策
- 監視・障害対応・脆弱性診断

**その他**
- 納品物の安全な受け渡し、PDF出力、通知、SEO/SSR
- AI連携（送信先・送信内容の明示と同意、APIキーのサーバー側管理）
